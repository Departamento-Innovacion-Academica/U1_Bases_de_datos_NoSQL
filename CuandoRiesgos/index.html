3.3.4 ¿Cuándo es útil BASE?

El modelo BASE resulta adecuado en escenarios como:

  • Redes sociales.
  • Catálogos de productos.
  • Métricas de visitas.
  • Recomendaciones de contenido.
  • Sistemas globales de lectura intensiva.
  • Aplicaciones donde unos segundos de desfase son tolerables.

En estos casos, la continuidad operativa suele ser más valiosa que la sincronización instantánea absoluta.

3.3.5 Tecnologías que aplican BASE o consistencia configurable

Diversas plataformas NoSQL utilizan este enfoque total o parcialmente:

  • Apache Cassandra.
  • Amazon DynamoDB.
  • Redis Cluster.
  • Azure Cosmos DB (niveles configurables).
  • Couchbase.

3.3.6 Ventajas del enfoque BASE

  1. Alta disponibilidad: el sistema continúa respondiendo durante fallos parciales.
  2. Menor latencia: no siempre requiere confirmación inmediata global.
  3. Escalabilidad horizontal: facilita expansión entre múltiples nodos y regiones.
  4. Resiliencia operativa: adecuado para plataformas 24/7 con usuarios globales.

3.3.7 Riesgos o limitaciones

También deben considerarse ciertos desafíos:

  • Lecturas temporales desactualizadas.
  • Conflictos entre actualizaciones concurrentes.
  • Mayor complejidad lógica en aplicaciones.
  • Necesidad de mecanismos de reconciliación.

Por ello, no todos los sistemas deben adoptar consistencia eventual.
